Architecture

Postgres decides. Redis times it.

Every email is a row in Postgres and a delayed BullMQ job keyed by its UUID. The worker is the only thing that talks to SMTP, and one atomic Lua call guards every send.

React dashboard

Vite · TanStack Query · typed API client · skeleton, empty and error states on every page.

Express API

Google OAuth · JWT httpOnly cookie · Zod validation · idempotency keys.

PostgreSQL

Prisma schema · source of truth for campaigns, emails, send logs and Slack connections.

Guarantees

Built for the boring failure cases.

Restarts, replays, limits and disconnects are the normal path, not the exception.

Delayed jobs only

Nothing polls a clock. Each email becomes a BullMQ delayed job with its UUID as the job id.

One atomic gate

Per-sender hourly counter, optional global counter and minimum spacing enforced in a single Redis Lua call.

Restart-safe

Startup recovery re-enqueues Postgres rows with no live job, so killing the API and worker mid-flight loses nothing.

Idempotent

Replaying a request with the same Idempotency-Key returns the original campaign instead of duplicating it.

Denied, not dropped

Over-limit jobs call moveToDelayed and raise DelayedError — they wait for the next window.

Honest states

Skeletons while loading, an empty state with a next action, and retryable error panels — never a blank screen.

Verification

Tested against the running stack.

Real HTTP calls, real Ethereal delivery, real process kills — not mocked assertions.
